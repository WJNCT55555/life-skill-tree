# 项目历程

这份文档记录这个系统从 v1 到现在的每一次结构性变化，以及**踩过的坑**。改代码之前值得看一眼——有些错误我踩过一次，不想你也踩一次。

---

## 版本脉络

| 版本 | 形态 | 节点 | 领域 | 关键变化 |
|---|---|---|---|---|
| v1 | 单文件 HTML | 100 | 8 | 第一版：100 天不重复任务、追问、成就、熔断卡 |
| v2 | PWA + 云同步 | 100 | 8 | 可装到手机主屏、离线缓存、口令制同步服务端（已删除，见下） |
| v3 | 单文件 HTML | 100 | 8 | 改为科技树：分支 × 层级解锁，加标签系统，删除短视频账本 |
| v3.1 | 单文件 HTML | 240 | 8 | 题库扩容、15 主题周 × 105 天、GitHub 风格热力图 |
| v3.2 | 单文件 HTML | 270 | **9** | 领域重组为九域（新增信仰，拆出魅力/能略） |

### 为什么删掉了 v2

v2 是 PWA 版：能装到手机主屏、有 Service Worker 离线缓存、带一个零依赖的同步服务端和完整的腾讯云部署文档。

删掉的原因不是它不好，而是**它会让你困惑该用哪个**。它的能力（手机可用）v3 用另一种方式覆盖了（单文件拷到手机即可），而它的代价（必须部署 HTTPS、要维护服务器、数据要手动同步）在你还没验证机制是否有效之前，都是纯浪费。

如果你想把它找回来，思路是现成的：v3 的 `data.mjs` + `nodes.mjs` 是纯数据，可以直接喂给任何前端模板。PWA 的 `manifest.json` + `sw.js` 加起来不到 60 行。

## 踩过的坑（按严重程度排序）

### 1. 用正则改结构化数据 → 数据全烂（最严重）

题库在 v3 里被整形过两次。我用正则匹配 `T('T001',...` 来定位节点，结果**正则跨分支贪婪匹配**，把 28 个节点插错了位置，导致：

- 「徒手爬上一棵树」被归到了「手工 · 生活自理」
- 任务的 id 和它的领域、分支、层级完全错位
- 元数据（出门/夜晚/花费）集体退回默认值

**第一次我用补丁去救，越救越乱**（改了 4 个一轮的脚本）。最后停下来做了三件事才对：

1. 把题库拆成独立的 `nodes.mjs`，作为唯一真相源
2. 改写脚本改用**括号深度解析**（逐字符扫描，跟踪 `[` `]` 深度和字符串状态），而不是正则
3. 删掉所有一次性整形脚本，只保留可重复运行的构建脚本

**教训：改结构化数据不要用正则猜结构。要么用解析器，要么老老实实重写整个文件。**

### 2. Windows 批处理不认识中文文件名

我把启动脚本命名为 `启动.cmd`。双击之后 cmd.exe 直接乱码：

```
'p0"' is not recognized as an internal or external command
'onode' is not recognized as an internal or external command
```

试了 UTF-8 和 GBK 两种编码保存，都不行——**问题不在文件内容，在文件名本身**：cmd 解析中文路径时用的是系统代码页，跟文件编码无关。

**解法：文件名用英文（`start.cmd` / `rebuild.cmd`），内容里也只用 ASCII。** 中文说明全部放文档里。

### 3. 构建脚本的默认路径错了 → 首次运行直接 404

服务端脚本原来写死 `path.join(__dirname, 'site')`，但站点实际在 `../site`。用户按文档敲命令，首页 404。

**解法：按优先级探测多个候选路径，谁先存在用谁**，并显式接受 `SITE_DIR` 环境变量覆盖。

### 4. 打卡之后「今天的账」面板不出现

逻辑写成了「打卡后立刻抽下一个节点」，于是刚完成的那件被替换掉，完成记录面板判定为"当前任务未完成"而隐藏。

**解法：做完之后不立刻换新卡**，让今天这张的完成记录留在眼前，明天零点由跨天逻辑自动发新的一张。

### 5. 夜间保护在凌晨 4 点还在生效

条件写成 `h >= 22 || h < 4`。凌晨 4 点打开时，系统只发"睡前向"节点，而「第 1 周」的节点全是夜晚类，于是**本周池子被抽空，抽卡逃到了第 9 周**。

**解法：收窄到真正的睡前时段 20:00-02:00。** 凌晨 2 点以后你已经醒了，硬塞"睡前任务"没有意义。

### 6. 抽卡拿到"24 小时数字断食"当第一个任务

新手第一天就被派 4 小时的硬仗，这是劝退级的错误。

**解法：加两道闸** —— 前 10 个只发轻量节点；任务时长不超过当日额度的 2 倍。（当时的"额度"是每日目标的分钟数，后来改成了体力系统，但这道闸保留了。）

### 7. 标签撞名导致筛选失效

按「出门」筛选返回了全部 100 个节点。原因是地点标签和时间标签里都有「出门」（`place:1` 和 `when:1` 撞名），且 `place:2`（荒野）也被映射成了「出门」。

**解法：拼标签时用 `Set` 去重**，并给时间档位改用「清晨/夜晚/周末」，不再用「出门」。

### 8. 已完成节点缺日期字段 → 整棵树渲染崩掉

在技能树里渲染已完成节点时直接取 `c.date.slice(5)`，如果某条记录缺 `date`，整个渲染流程抛异常，页面白屏。

**解法：改防御性写法** `(c && c.date) ? String(c.date).slice(5) : ''`。用户数据里只要有一条异常，就不该让整棵树挂掉。

## 构建脚本的校验清单

这些校验不是装饰——上面 8 个坑里有 6 个是被它拦下来的，另外 2 个（中文文件名、路径）它管不到。

| 校验项 | 拦下过什么 |
|---|---|
| 领域必须 9 个、分支必须 27 条 | 改领域时漏改分支 |
| 节点总数 ≥270 | 扩容没生效 |
| 每条分支层级从第 1 层连续、每层最多 2 个 | 加了节点导致某层有 3 个 |
| 任务名 4-16 字、**不带标点** | "拆开它，再装回去"这种写成句子的名字 |
| 描述 ≥25 字 | "看一场电影"这种愿望级条目 |
| 不能有重复标题、重复"为什么" | 复制粘贴时的疏漏 |
| 主题周必须刚好 15 × 7 = 105 天 | 周次分配没填满 |
| 因果链不能有环、前置不能比自己更晚 | 逻辑倒挂（"做完 A 才能做 B，但 A 比 B 靠后"） |
| QSET 必须覆盖所有领域 | 改领域键名时漏改追问模板 |

**原则：坏数据进不了成品。** 宁可拒绝构建，也不生成一个看起来正常、用起来出错的东西。

## 设计取舍记录

**为什么题库要 301 个，而主线只有 105 个？**
105 是主线（15 周 × 7 天），剩下的 196 个是备选池。这样每周的池子里有 2-3 倍的选择余量，而且做完一轮还能重玩。**题库如果只有 105 个，"每天一件新事"就会变成"每天一件被指定的事"。**

**为什么允许跨周完成？**
主线是为了给你方向，不是为了绑架你。今天突然想做「写一份遗嘱」，不该因为"这属于第 15 周"而被拦住。**日程服从人，不是人服从日程。**

**为什么信仰领域单独存在？**
前八个领域都在回答"我能做什么"，只有信仰在回答"我为什么活着"。海因莱因那句话里最重的两个短语——"安慰濒死的人""勇敢地死去"——不属于任何技能分类。**把它们塞进"相处"或"心性"里，是对这两个问题的降级。**

**为什么删掉了"属性"层？**
早期版本给每条分支挂了一个属性标签（勇气/逻辑/创造…），想用 9 个维度概括"你在长成什么人"。但属性跟分支是 1:1 对应的——勇气 只挂在 极限+突破 上，建造 只挂在手工三条线加 饮食 上。**信息完全重合，等于同一件事说了两遍。** 删掉之后分支名（统一 2 字）直接承担这个职能，少一层抽象、少一次翻译。

教训：**如果一个维度的信息能被另一个维度完全推导出来，那它就是噪音。**

**为什么追问要按领域定制？**
问一个做「写一份遗嘱」的人"这件事的感官细节是什么"，是荒谬的。信仰领域的追问必须是：你真的相信吗 / 最难面对的是哪一段 / 如果这是真的，你明天会改什么。**问题问错了，思考就不会发生。**

## 如果你要接手这个项目

1. **先读 `nodes.mjs` 的注释头**，那里写清了节点字段格式和写法规范
2. **改任何东西之后跑一次构建**，校验会告诉你哪里错了
3. **不要用正则改 `nodes.mjs`**，用解析器（`build.mjs` 里有现成的括号深度扫描函数）
4. **文件名保持英文**（Windows 批处理的限制）
5. **`.cmd` 文件内容只用 ASCII**
